# F1-22 R2 — checkpoint шаблона и проверка перед сохранением

Компонент сохраняет выбранный языковой шаблон в воспроизводимый JSON checkpoint и восстанавливает его с проверкой целостности. Перед передачей материалов в сохранение он сопоставляет checkpoint с результатом реальной текущей цепочки F130 → F120 → F122 → consumer. При расхождении сохранение не вызывается.

## Что реализовано

В [sales_template_checkpoint.py](F1-22_Dmitriy_Stazher_R2/source/sales_template_checkpoint.py) реализованы три функции:

| Функция | Назначение |
| --- | --- |
| `capture_checkpoint` | Проверить данные через реальный F122, получить канонические UTF-8 байты и SHA-256 payload. |
| `materialize_checkpoint` | Проверить формат, каноничность, digest и закреплённые версии; вернуть результат реального F122. |
| `prepare_checkpoint_materials` | Выполнить реальную текущую цепочку F130, сопоставить материалы с checkpoint и один раз вызвать переданный callback сохранения. |

Проверяются точные типы, повторяющиеся JSON-ключи, UTF-8, surrogate, циклы, глубина до 64 контейнеров и размер до 1 048 576 байт включительно. Соблюдён порядок контрактных ошибок. Тексты, пробелы и порядок фактов сохраняются. Результат и исключение callback передаются с сохранением идентичности объекта; повторных попыток нет.

## Повторить проверки

После клонирования перейдите в каталог пакета:

```bash
cd F1-22_Dmitriy_Stazher_R2
python -B CHECK_PACKAGE.py
python -B RUN_CHECKS.py baseline
python -B RUN_CHECKS.py candidate
python -B RUN_CHECKS.py own
```

В Windows при необходимости используйте `py -3.12 -B` вместо `python -B`. Проверки не требуют БД, внешних сервисов или ключей.

Для повторной сборки с двумя чистыми прогонами выполните **из корня репозитория**:

```bash
python -B F1-22_Dmitriy_Stazher_R2/source/tests/checkpoint/helper_return.py --repo .
```

Новая сборка обновляет фактические времена и логи, поэтому её SHA-256 будет отличаться от опубликованного архива.
